# Slumpad barrunda

## What it is
- A static website for a bar crawl. About 20 people use it at the same time, each on their own phone.
- Each person has a **"Till nästa bar"** button. Pressing it picks a random bar from the list and shows its name, its address and a **"Visa på karta"** link (Google Maps).
- **Rounds of a fixed length.** `"antal"` in `barer.json` sets how many bars a round has, the last bar included.
  - The first `antal − 1` stops are drawn at random from the **pool**: every bar not marked `sist`. The pool can be bigger than that, so different phones get different bars.
  - The last stop is always the bar marked `"sist": true`.
  - A bar is **never repeated within a round**. After the round, the history resets silently and randomizing carries on. The bar just shown is excluded from the first pick after the reset, so it can't come up twice in a row.
  - Without `antal` (or with a plain array), a round is every bar in the list.
- Each phone randomizes **independently**. There is no server, no sync and no shared state between users.
- A small **"Börja om"** button clears the history, after a confirmation dialog.
- **A shared last bar.** The bar marked `"sist": true` in `barer.json` is always the last stop of the round, so everyone's crawl ends there.
  - When it comes up, the coaster shows a "Kvällens sista bar!" tag.
  - After it, the silent new round starts as usual, and the marked bar is again held back until the end.
- A small **"Ångra"** button takes back picks, for accidental taps. It's **multi-step**: each press undoes one more pick, all the way back to the start of the night ("Var börjar kvällen?").
  - Each undo restores the previous bar and visited list.
  - It's disabled when there's nothing to undo, and during the roll.
  - It survives a reload, and works across the silent new-round reset.
  - "Börja om" clears the undo history.
  - **Undo can't be used to pick a bar.** Every undone bar goes onto a *replay queue*, newest first. The next rolls take bars from that queue, so undoing N times and rolling N times replays exactly the same bars in the same order. The roll still animates as normal.
    - The queue survives reloads and "Börja om".
    - Only clearing the browser's site data gets around it, which no static site can prevent.
  - **Rewind effect:** about 0.35s with the `is-rewinding` class.
    - The coaster spins backwards, twice as fast as the roll, under scrambled letters, and the beer bubbles sink.
    - It then settles on the old bar with a mirrored wobble (`is-rewound`). `fest.js` pops a mint **"◀◀ Ångrat"** badge; the ◀◀ is a CSS clip-path, not an emoji.
    - `app.js` fires `barrunda:rewind` at the start, which clears leftover confetti, and `barrunda:undo` at the end.
    - Under reduced motion there's no spin, and the badge shows still for 1.5s.

## Hard requirements
- **Static only**: plain HTML, CSS and JS. No build step, no framework, no npm dependencies at runtime.
- **Hosted on GitHub Pages** from the `main` branch, repository root. `.nojekyll` keeps Pages from running Jekyll.
- **Swedish only**: all visible text, `aria-label`s, `<title>`, dialogs and error messages are in Swedish. `<html lang="sv">`.
- **Mobile-first**: designed for phones in portrait (about 360 to 430px wide). The primary button sits in the thumb zone, with tap targets of at least 44px. Use `100dvh` and safe-area insets. Desktop only needs to look fine, centred.
- **Visited bars are saved in the browser** (`localStorage`). Every storage call is wrapped in try/catch. If storage is blocked (private mode), the app still works in memory for the session.

## Files
- `index.html`: the one screen.
- `style.css`: page styles. Line 1 is the Hallmark stamp.
- `tokens.css` and `base.css`: generated by the Hallmark scaffold. Don't hand-edit them. Regenerate with `theme.mjs scaffold`.
- `app.js`: all logic.
- `barer.json`: **the editable bar list** (see below).
- `.hallmark/log.json`: the Hallmark build log. `.hallmark/shots/` holds sloplint screenshots and is git-ignored.

## The bar list (`barer.json`)
- A JSON object: `{ "antal": 4, "barer": [ ... ] }`.
  - `antal` is the round length, including the last bar. It's capped at the number of bars. With `antal: 4`, five bars and one marked `sist`, everyone gets 3 of the other 4, then the last bar.
  - A plain array of bars also works. The round is then every bar.
- Each entry in `barer` is `{ "namn": "Barens namn", "adress": "Gatan 1, Stad" }`.
- Optional `"karta": "https://..."` overrides the generated Google Maps link (use it when a name search finds the wrong place).
- Optional `"sist": true` marks **the shared last bar** of the night. Only the first bar marked counts. Remove the field (or set it to `false`) if the crawl should have no fixed ending.
- `namn` is required and must be **unique**: it's the key stored in each visitor's history. Renaming a bar makes it count as a new, unvisited bar. Removed bars are ignored in old histories.
- The list is fetched with `cache: "no-cache"`, so edits show up on the next page load after Pages redeploys (usually within a minute or two).
- Keep the JSON valid: double quotes, commas between entries, no trailing comma. If the file fails to parse, the site shows its error state.

## Storage keys
- `slumpad-barrunda:besokta`: a JSON array of visited bar names for the current round. The header shows "N av antal besökta".
- `slumpad-barrunda:aktuell`: the name of the bar currently shown, so a reload keeps it on screen.
- `slumpad-barrunda:historik`: a stack of `{ visited, current }`, one entry from just before each pick, newest last, capped at 200. "Ångra" pops from it; "Börja om" clears it.
- `slumpad-barrunda:ko`: the replay queue, a JSON array of bar names that undos took back, next first. Each roll takes from its front.
- The old single-step keys `slumpad-barrunda:forra` and `slumpad-barrunda:last` are deleted on every save.

## Screen states
- Every state must exist and stay in Swedish:
  - **Loading:** a skeleton.
  - **Empty:** no bar picked yet.
  - **Error:** the list couldn't be read, or it's empty.
  - **Full:** the current bar.
- The shuffle animation uses only `transform` and `opacity`. Under `prefers-reduced-motion: reduce` the pick appears instantly.

## The chosen design: "Aperitivo", party version ("fest")
- Hallmark's **Darkroom** theme with a custom party colourway:
  - A raspberry ground, with still confetti dots behind the coaster area only, never behind text.
  - A cream beer coaster in the centre with berry type and a dashed hot-pink ring.
  - Five confetti colours: the `--color-party-*` tokens.
- The primary button is a **beer**: an amber body, a scalloped foam head (`::before`), and bubbles that rise inside it while rolling (`::after`).
- **`fest.js`** holds the party effects. It listens for the `barrunda:landed` event from `app.js` and throws a confetti burst plus a "Skål!" that pops and fades. It's pure decoration: aria-hidden, cleaned up after 1.6s, and off under reduced motion. `app.js` also fires `barrunda:roll` when a roll starts.
- Keep confetti colours away from cyan on the dark ground: sloplint fails it as a "cyan-on-dark gradient" (gate 2a).
- Faces: Sofia Sans Extra Condensed at 800 (headings, wordmark, buttons) and Barlow at 400 (body). No other weights.
- The colourway lives in the `:root` block at the top of `style.css` and **overrides** `tokens.css`. Change colours there, never in `tokens.css`.
- The roll is **anonymous**: while it runs, the coaster spins under 6 to 10 random letters (`scramble()` in `app.js`). Never show real bar names during the roll.
- When the roll lands, the coaster settles with a wobble. Under reduced motion it lands instantly with no spin.

## Design: Hallmark skill (`~/.agents/skills/hallmark`)
- Hallmark builds this as an **app screen** (`shape: app screen`), not a marketing page.
- Every colour and font goes through a token on `:root`. No literal colours or `font-family` outside `tokens.css`.
- Never use `transition: all`. Never animate `width`, `height`, `top` or `left`.
- Use `overflow-x: clip` on `html` and `body`, never `hidden`.
- Every interactive element has `:focus-visible`. Every animation has a reduced-motion fallback.
- No eyebrows, no tracked small caps, no emoji as icons, no invented numbers. The only figure shown is the real visited count.
- The first line of `style.css` is the Hallmark stamp, then the critique line.
- Before handing back a design change, run `node ~/.agents/skills/hallmark/scripts/sloplint.mjs index.html style.css --genre atmospheric --scope app --render --url http://localhost:<port>/` with a local server running, and fix every FAIL.
  - The `--render` tier needs `puppeteer-core`, found through `HALLMARK_PUPPETEER=<folder with node_modules>`. On this machine there's no Chrome, so also set `CHROME_PATH` to Edge (`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`).

## Run locally
- `npm start` (serves on `http://localhost:5173`; `package.json` has only scripts, no dependencies), or `npx serve .` or `python -m http.server 8000`. The python server uses `http://localhost:8000`. Opening `index.html` straight from disk (`file://`) blocks the `fetch` of `barer.json`.
- To test on a phone, use the same Wi-Fi and open `http://<computer-ip>:8000`.
